# MMORPG — контекст проекта

## Суть
Браузерная онлайн-MMORPG. Игроки заходят через интернет и видят друг друга в реальном времени.
**Референс по графике и геймплею: RPG MO** — 2D, вид сверху/изометрия, тайловая карта, спрайты,
кликами ходим, бьём мобов, собираем лут, прокачка, инвентарь.

## Главный принцип
Игра должна быть **онлайн** — это её смысл. Поэтому есть сервер, который держит общий мир
и синхронизирует всех игроков через WebSocket.

## Архитектура
- **Клиент** (`client/`) — браузер, HTML5 Canvas + JS. Рисует карту, игроков, обрабатывает ввод.
- **Сервер** (`server/`) — Node.js + Socket.IO. Хранит состояние мира, синхронизирует игроков.

## Где что крутится
- **Разработка** — на Mac (эта папка на рабочем столе).
- **Боевой сервер** — на втором компе пользователя под **Windows** (постоянно включён).
- **Доступ из интернета** — через **Cloudflare Tunnel** (бесплатно, безопасно, постоянная ссылка).
  Друзья просто открывают ссылку в браузере.
- Пользователь во Вьетнаме (UTC+7).

## Стек
- Node.js + Socket.IO (сервер)
- HTML5 Canvas (клиент, без тяжёлых движков на старте)
- Без сборщиков на старте — простой статичный клиент

## Архитектура (после рефакторинга — модульная, контент на данных)
Принцип: КОНТЕНТ = ДАННЫЕ, а не код. Сотни мобов/предметов = записи в json + одна система.

**Сервер** (`server/`, CommonJS-модули):
- `server.js` — точка входа: подключает модули, запускает. Тонкий.
- `config.js` — все настройки/баланс (HP, урон, тики, тайлы). `util.js` — rnd, adjOrtho.
- `world.js` — карта (владеет MAP/W/H), load/save, isWalkable, randomSpawn, setMap, getState.
- `players.js` — объект players, create/remove/count/respawn.
- `mobs.js` — мобы из data/mobs.json, mobAt, playerCanStep, publicMobs, kill.
- `combat.js` — боевой тик (start(io)). `net.js` — все socket-обработчики (setup(io)).
- `data/` — КОНТЕНТ: `mobs.json` (types+spawns), `default-map.json` ✅ подключены;
  `items.json`, `resources.json` 🟡 каркас на будущее. См. `data/README.md`.
- Зависимости однонаправленные: world←players←mobs←combat/net (без циклов). MAP наружу не отдаём
  как переменную (переприсваивается) — только через функции world.

**Клиент игры** (`client/`, ES-модули, грузятся по http):
- `index.html` → `<script type="module" src="js/main.js">`.
- `js/state.js` — общий объект S со всем изменяемым состоянием (избегаем live-binding проблем).
- `js/config.js` (SCALE/TW/TH/цвета), `js/iso.js` (isoX/isoY/screenToTile), `js/ui.js` (HUD/floaters).
- `js/net.js` (socket-события), `js/input.js` (ввод/путь/бой), `js/render.js` (рендер), `js/main.js` (вход+цикл+setupUi).
- `js/ui.js` — HUD: updateHpHud (панель игрока), updateTargetHud (панель HP врага).

- Низ право: 🎒 инвентарь и ☰ меню (кнопка «Выход» = location.reload()). Взаимоисключающие.
- Инвентарь: сетка 8×4 = 32 слота (заглушка), под ней золото иконкой `🪙 N` (`#goldAmount`).
  Золото = поле player.gold на сервере (пока 0, под будущий лут), приходит в init, ui.updateGold().
- Подсказка-название сверху по центру (`#tooltip`): при наведении на моба (input.js mousemove → showTip с
  TYPE_NAMES) и на кнопки с `data-tip` (main.js). ui.js: showTip/hideTip.
- Всё строится в main.js → setupUi().
- ИКОНКИ — свои inline-SVG (не эмодзи): рюкзак (инвентарь), гамбургер (меню), монета (золото).
  Лежат прямо в index.html. Для новых иконок — рисуем SVG так же.
- `window.S` выставлен для отладки в консоли.
- ВАЖНО: client-test (одиночка) — НЕ ES-модули (file://), остаётся монолитным test.js.

## Инвентарь, снаряжение, добыча ресурсов
- Предметы — в `data/items.json` (`items`: axe/wood/sword). Игрок стартует с топором.
- Сервер: players.js хранит `inventory [{id,qty}]`, `hotbar[6]`, `activeSlot`, `gathering`.
  Хелперы addItem (стак), activeTool, invState, hasItem. `resources.js` — деревья как ноды (из тайлов
  type=TREE), цикл рубки (GATHER_TICK_MS=700): −1 от дерева, +1 wood игроку; дерево даёт TREE_AMOUNT=4,
  потом истощается и отрастает через RESOURCE_RESPAWN_MS=15с. canChop(tool)=axe.gathers==='tree'.
  TREE_AMOUNT=30 (30 ударов до пня, 1 древесина за удар).
- Хотбар хранит САМИ предметы (стаки {id,qty}), не ссылки: перенос в слот УБИРАЕТ предмет из рюкзака.
  Новый лут (addItem) всегда идёт в рюкзак, никогда в хотбар. activeTool читает hotbar[activeSlot].id.
- net события: `invToHotbar{invIndex,slot}` (занятый слот — обмен), `hotbarToInv{slot}`, `activateSlot(slot)`,
  `gather{x,y}`. Бой и рубка гасят друг друга. На клиенте DnD передаёт {from:'inv'|'hot',index}; рюкзак и хотбар —
  взаимные drop-цели (туда и обратно).
  init шлёт inventory/hotbar/activeSlot (в `you`) и `depleted` (срубленные деревья). `inventoryUpdate` — при изменениях.
- Клиент: `js/items.js` (имена+SVG-иконки axe/wood, TREE_NAME). ui.renderInventory/renderHotbar. Перенос —
  HTML5 drag-and-drop из инвентаря в слот хотбара; клик по слоту = activateSlot (жёлтая рамка = активен).
  Клик по дереву с активным топором → подойти → gather; иначе floater «Нужен топор». Срубленное дерево —
  пень (render drawTree depleted), S.depletedTrees (set "x,y"). gatherHit → floater «+1».
  S.pendingAction = {kind:'attack'|'gather',...} (бывший pendingAttack). Тултип «Дерево» при наведении.
- НЕ сделано: дроп предметов на землю, использование/крафт, перетаскивание внутри инвентаря, тач-DnD.

## Персонаж (стиль и слои) — в работе, ещё НЕ в игре
- Стиль выбран по референсам пользователя (3 SVG на Desktop, flaticon-флэт): ПЛОСКО, БЕЗ ЛИЦ,
  cel-тени в 2 тона (свет слева → правая половина/правая конечность темнее), без обводок/градиентов.
- Базовое тело — «стройный» (вариант №3), доработан: голова приклеена к шее, у ног плоский верх под туникой,
  руки с локтем и раздвинуты, ноги расставлены, компактные пропорции, держит предмет в правой руке.
- Техника: каждая деталь — путь; центр-сплит тени через clipPath (левая=shade(+9), правая=shade(-20)).
  Конечности — сплошной 2-тон по стороне (левая светлее, правая темнее).
- МОДЕЛЬ «БУМАЖНАЯ КУКЛА»: сначала рисуется ТЕЛО-КОЖА целиком (ноги бедро+голень, руки плечо+предплечье,
  торс, кисти, голова), затем одежда/броня слоями ПОВЕРХ. Где не закрыто — видна кожа (безрукавка→голые руки,
  шорты→голые голени). ОДИН предмет на слот → из-под него ничего не торчит. Броня чуть КРУПНЕЕ части тела
  (шлем больше головы и т.д.) и садится поверх. Конечности нарисованы посегментно (плечо/предплечье, бедро/голень),
  чтобы одежда закрывала их частично (рукава/штаны разной длины).

## Запуск
- **Проще всего:** двойной клик по `▶ Запустить игру (сервер).command` — сам поставит зависимости
  (при первом запуске), поднимет сервер и откроет игру в браузере. Окно Терминала держит сервер живым;
  закрыть окно / Ctrl+C — остановить. Если порт 3000 занят — просто откроет браузер.
- Вручную: `cd server` → `npm install` (один раз) → `npm start`.

## Изометрия (визуал)
- Тайлы-ромбы 2:1, базовые TW=64 TH=32, умножены на SCALE=1.6 (крупный масштаб). Стены — кубы (WALL_H=34*SCALE), деревья (TREE_H=46*SCALE). В game.js все пиксельные размеры рисунка тоже *SCALE.
- В client-test/ масштаб задаётся стартовым zoom=1.6 (колесо меняет).
- Объекты сортируются по глубине (x+y) для правильного наложения.
- Тайлы: 0 трава, 1 вода(блок), 2 стена(блок), 3 дерево(блок), 4 тропа. BLOCKED={1,2,3}.
- Движение ПЛАВНОЕ (без прыжков по клеткам): постоянная скорость MOVE_SPEED=4.5 клеток/сек.
  input.js: glide() двигает rx,ry к логической клетке x,y с пост. скоростью; decideStep() выбирает
  следующий шаг ТОЛЬКО когда доехал (rx≈x), без пауз → непрерывная ходьба. glide телепортит при dist>2 (респаун).
- Мобов на карте сейчас 3 (по 1 каждого вида) — в data/mobs.json.
- Управление в игре: КЛИК по тайлу — идти туда (BFS поиск пути, 4 направления, обход препятствий,
  жёлтый маркер цели; клавиатура/тач отменяют путь). Плюс WASD/стрелки = 4 диагонали (NE/NW/SW/SE).
  screenToTile = инверсия изометрии через originX/originY. Клик-перемещение есть и в game.js, и в client-test/.

## Мобы и бой (Этап 3)
Сервер владеет мобами и боем (server.js): MOB_TYPES (friendly/passive/aggressive), MOB_SPAWNS (в коде,
8 шт; позже — через редактор), боевой тик COMBAT_TICK_MS=900, RESPAWN_MS=10000, PLAYER_MAX_HP=30.
- friendly 🟢 (бить нельзя/не атакует), passive 🟡 (бьём — отвечает), aggressive 🔴 (сам цепляет с ПРЯМОЙ соседней клетки).
- Бой пошаговый: ОДИН удар за тик (COMBAT_TICK_MS=650), строго ПО ОЧЕРЕДИ. Первым бьёт инициатор:
  игрок кликнул моба → player.turn='player' (я первый); красный напал сам (агро-захват) → turn='mob' (он первый).
  У игрока поле turn ('player'|'mob') чередуется после каждого удара. Анти-эксплойт: повторный 'attack' по той же
  цели не сбрасывает очередь (turn ставится только при НОВОЙ цели). Моб умер → исчез → респаун через 10с.
- Игрок: hp/maxHp, смерть → respawnPlayer (новый спавн, полный HP). У игрока поле `target` (id моба).
- Живой моб занимает клетку: `playerCanStep = isWalkable && !mobAt`. Движение и BFS обходят мобов.
- Клиент (game.js): клик по мобу → approachMob (подойти вплотную) → emit 'attack'. mobAt/canStep/adjOrtho.
  События: combatHit{target,id,hp,dmg}, mobDied, mobRespawned, playerRespawn. HP-бары, цифры урона (floaters),
  hurtFlash/deathFlash («Вы погибли»), HUD #hpHud. Дружественных клик не атакует.
- ВАЖНО (анти-рассинхрон): сервер при невалидном `move` шлёт откат `playerMoved` с серверной позицией.
- Бой — ТОЛЬКО в игре (нужен сервер). В client-test (одиночка) мобов нет — это инструмент для карты/визуала.
